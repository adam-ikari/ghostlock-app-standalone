# 交接：设备回来后怎么把最后两步跑完

> 2026-10-21 20:20 收尾时手机已从宿主上断开（`adb devices` 看不到设备），最后两件需要真机的事留给下一次。

## 一、真机门禁（必须做：仓库里的 native 刚改过，设备上跑的还不是这版）

改动内容（`vendor/ghostlock-app` 的 `src/core/attack/ops.cpp`）：把编排同步成**设备上验证过**的顺序——
`su` 域装模块 / 先删旧模块目录 / 等 zygote 最多 60s / **再等 60s** 才起 Vector daemon。

```bash
# 0) 传文件（宿主 → 我的环境）通道：宿主上的 dufs(65496, --allow-upload) + cloudflared
#    隧道 URL 见 /c/work/titan2/ct6.err 里那行 trycloudflare.com
curl -H 'Authorization: Bearer <token>' -T ghostlock-v584 <tunnel>/ghostlock-v584

# 1) 宿主上：新 native 推上手机
adb push ghostlock-v584 /data/local/tmp/ghostlock
adb shell chmod 755 /data/local/tmp/ghostlock

# 2) 干净跑一次（KernelSU 已在内存里时 native 会跳过利用，先重启手机清掉）
adb reboot
#    等 adb 回来后：
adb shell 'rm -f /data/local/tmp/gl.log /data/local/tmp/.ghostlock_ksu.log'
adb shell 'nohup /data/local/tmp/ghostlock --load-prebuilt-profile /data/local/tmp/profile.bin > /data/local/tmp/gl.log 2>&1 &'
sleep 150      # 利用(~40s) + 装模块 + 等 zygote(≤60s) + settle 60s + daemon

# 3) 验收：日志里这一串要出现
adb shell 'sed -n "/modules dir/,\$p" /data/local/tmp/.ghostlock_ksu.log'
#   期望：installing module … → module install exit=0（两次）→ late-load exit=0
#        → zygote patched=1 → waiting 60s → starting Vector daemon
#        → == vector cli status == Framework Version: 2.2 / API Version: 102
#        → == zygisk next status == zygote_states:1 modules64:1,zygisk_vector
adb shell 'su -c "/data/adb/modules/zygisk_vector/cli status"'
```

失败就按 `docs/titan2-ondevice-flow.md` 的「五个坑」排查（最常见：装模块 Permission denied → 没走 su；
`i/o error` → 旧目录没删；framework 起不来 → settle 时间不够）。

## 二、cmp_disasm（上游 `AGENTS.md` 要求：攻击路径改动要有 8 个函数 IDENTICAL 的结论）

```bash
cd vendor/ghostlock-app
```
