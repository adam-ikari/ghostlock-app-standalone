## 🔴 阻塞项：仓库里的 native 编排 ≠ 设备上验证过的那版

`src/core/attack/ops.cpp` 的「Titan 2 集成」段提交的是**第一版**（18:0x 之前），
而设备上真正跑通的是**后两版**（stack3/stack4，只在设备上、没进仓库）。差四处：

| # | 仓库现状 | 设备上验证过的 | 不改会怎样 |
| --- | --- | --- | --- |
| 1 | `"$KSUD" module install "$z"`（root 脚本在 **shell 域**） | 先 `late-load` 拿到 su，再 `su -c "/data/adb/ksu/bin/ksud module install $z"`（**ksu 域**） | `Permission denied`：写不了 `/data/adb/modules_update`；ksu 域也执行不了 app 目录里的 `libksud.so` → **模块装不上** |
| 2 | 没有先删旧模块目录 | `rm -rf /data/adb/modules/{zygisk_vector,zygisksu}` 再装 | `i/o error: No such file or directory`（看着像 bug，其实是旧目录残留）→ 装不上 |
| 3 | 等 zygote 只等 **20×1s** | 最多 **60×1s** | 注入还没挂上就往下走 → 后面第 4 步的 system_server 重启循环 |
| 4 | 挂上后**立刻**起 Vector daemon | 挂上后**再等 60s** | **framework 起来一半挂掉 → rescue party → 进 recovery**（实测 3 次挂 2 次；recovery 里 adbd 关着，只能长按电源键） |

另外仓库版缺「late-load (pre-modules)」这一步（第 1 项的前置：su 要先有）。

> 这四条是这次会话里最花时间换来的（每次失败都要一次 recovery + 一次用户手动重启），
> 必须先同步进仓库，再出 APK。

## 🟠 需要决策的问题

1. **把 GPL 模块 zip 打进 Apache-2.0 的 app**：`assets/modules/{vector.zip,zygisknext.zip}`
   是 Vector（LSPosed 系，GPL-3.0）与 ZygiskNext（GPL-3.0）的官方构建。
   自用没问题，**但要往上游提 PR 就是许可冲突**。→ 建议：内置改成「首次运行时从用户指定的
   本地文件装」或直接不做内置（模块管理器 app 自己去商店装），app 只负责 root。
2. **`/data/data/*/files/modules` 这个兜底 glob**：root 能读所有 app 的私有目录，
   多个 app 各自摆 zip 时会**挑错目录**。建议改成只认 runtime home + 显式环境变量，
   Shizuku 路径则由 app 通过 UserService 传参（协议要动，属 L 级改动）。
3. **`RootStatus` / `rootStatus()` 是死代码**：仓库里恒为 `UNKNOWN`（Shizuku 探针被回退了，
   因为 API 13.1.5 的 `Shizuku.newProcess` 是 `@RestrictTo` 编译不过）。
   现在「设备已 root」只靠 native 日志里那行 `already has root` 驱动
   （`noteRootState()`）。→ 要么把 `RootStatus` 与 `rootStatus()` 删掉，要么把探针换用
   app 自己的 UserService 实现。
